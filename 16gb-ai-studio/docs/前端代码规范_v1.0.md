# GMae-16GAS 前端代码规范 v1.0

> **目的**：统一前端代码风格，防止代码腐烂，确保可维护性。
> **适用范围**：vram-console/web/ 目录下所有前端代码（HTML/CSS/JS）。
> **创建**：2026-09-03 ｜ 基于代码质量整改 P2-4 项。

---

## 一、文件结构规范

### 1.1 目录结构

```
web/
├── index.html              # 入口HTML（仅结构，不含业务逻辑）
├── css/
│   ├── variables.css       # CSS变量（颜色/间距/字体）
│   ├── base.css            # 样式重置 + 基础样式
│   ├── layout.css          # 布局（Header/Sidebar/Content/网格）
│   ├── components.css      # 通用组件（Button/Card/Table/Modal等）
│   └── pages/
│       ├── common.css      # 页面通用组件（显存条/时间线/卡片等）
│       └── topology.css    # 拓扑图特定样式
└── js/
    ├── app.js              # 入口文件（≤200行，仅初始化和路由）
    ├── core/
    │   ├── utils.js        # 工具函数（≤100行）
    │   ├── eventbus.js     # 事件总线（≤50行）
    │   ├── state.js        # 全局状态管理（≤50行）
    │   ├── api.js          # API调用封装（≤150行）
    │   └── router.js       # 路由管理（≤100行）
    ├── components/
    │   ├── icons.js        # SVG图标（≤50行）
    │   ├── toast.js        # Toast通知（≤50行）
    │   └── modal.js        # 模态框（≤50行）
    └── pages/
        └── pages.js        # 页面渲染逻辑（可进一步拆分）
```

### 1.2 文件大小限制

| 文件类型 | 最大行数 | 说明 |
|---------|---------|------|
| 入口文件（app.js） | 200行 | 仅初始化和路由，不含业务逻辑 |
| 核心模块（core/） | 150行 | 工具/状态/API/路由 |
| 组件模块（components/） | 100行 | 通用UI组件 |
| 页面模块（pages/） | 500行 | 超过则按子页面拆分 |
| CSS文件 | 500行 | 超过则按功能拆分 |

**超过限制必须拆分**，不允许"暂时放这里"。

## 二、命名规范

### 2.1 JavaScript 命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 变量/函数 | camelCase | `getVramUsage`, `currentScene` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRIES`, `API_BASE_URL` |
| 类/构造函数 | PascalCase | `VramChart`, `EventBus` |
| 全局对象 | camelCase | `appState`, `eventBus` |
| 布尔变量 | is/has/can 前缀 | `isLoading`, `hasError`, `canRelease` |
| 事件名 | kebab-case | `vram-updated`, `scene-changed` |

### 2.2 CSS 命名

采用 BEM 简化版：

```css
/* 块 */
.card { }

/* 块__元素 */
.card__header { }
.card__body { }

/* 块--修饰符 */
.card--warning { }
.card--compact { }
```

**禁止**：
- 禁止使用 ID 选择器（`#my-id`），全部用 class
- 禁止嵌套超过3层
- 禁止使用 `!important`（除非覆盖第三方库）
- 禁止内联样式（除非动态计算）

### 2.3 HTML 命名

- `id`：kebab-case（`vram-chart`, `modal-overlay`）
- `class`：BEM 规范
- `data-*`：kebab-case（`data-scene-id`, `data-model-name`）

## 三、函数规范

### 3.1 函数长度

- **单函数最大 50 行**（不含注释和空行）
- 超过必须拆分为子函数
- 每个函数只做一件事（单一职责）

### 3.2 函数参数

- 参数不超过 4 个，超过用对象传参
- 必须有默认值（可选参数）

```javascript
// 好
function renderChart(container, data, options = {}) { }

// 坏
function renderChart(container, data, width, height, color, fontSize, showLegend) { }
```

### 3.3 返回值

- 统一返回对象 `{ ok: bool, data: any, error: string }`
- 异步函数必须返回 Promise
- 不允许返回 `undefined` 表示失败

## 四、错误处理规范

### 4.1 API 调用

```javascript
// 所有 API 调用必须有 try-catch
async function fetchVramData() {
    try {
        const response = await api.get('/api/vram/status');
        if (!response.ok) {
            throw new Error(`API error: ${response.status}`);
        }
        return { ok: true, data: response.data };
    } catch (error) {
        console.error('[vram] fetch failed:', error);
        toast.error('显存数据获取失败');
        return { ok: false, error: error.message };
    }
}
```

### 4.2 禁止静默吞异常

```javascript
// 禁止
try {
    doSomething();
} catch (e) {
    // 什么都不做
}

// 必须
try {
    doSomething();
} catch (e) {
    console.error('[module] action failed:', e);
    // 或：toast.error('操作失败');
    // 或：return { ok: false, error: e.message };
}
```

### 4.3 用户反馈

- 所有用户操作必须有反馈（成功/失败/加载中）
- 成功：toast.success 或 UI 状态更新
- 失败：toast.error + 控制台日志
- 加载中：按钮禁用 + loading 状态

## 五、CSS 规范

### 5.1 变量优先

所有颜色、间距、字体必须使用 CSS 变量：

```css
/* 好 */
.card {
    background: var(--bg-card);
    border: 1px solid var(--border);
    padding: var(--spacing-md);
    color: var(--text-primary);
}

/* 坏 */
.card {
    background: #1a1a2e;
    border: 1px solid #333;
    padding: 16px;
    color: #fff;
}
```

### 5.2 响应式

- 移动端优先（mobile-first）
- 断点：`--breakpoint-sm: 640px`, `--breakpoint-md: 768px`, `--breakpoint-lg: 1024px`
- 使用 `clamp()` 处理流体排版

### 5.3 性能

- 避免使用 `box-shadow` 动画（用 `transform` 替代）
- 避免频繁重排（用 `transform`/`opacity` 动画）
- 大图必须懒加载

## 六、代码质量检查清单

提交前必须检查：

- [ ] 所有文件不超过行数限制
- [ ] 所有函数不超过50行
- [ ] 所有 API 调用有 try-catch
- [ ] 没有静默吞异常（空 catch）
- [ ] 没有 `console.log` 调试代码（用 `console.error` 记录错误）
- [ ] 没有硬编码的颜色/间距（用 CSS 变量）
- [ ] 没有 ID 选择器（用 class）
- [ ] 所有用户操作有反馈
- [ ] 变量命名符合规范
- [ ] 函数命名符合规范（动词开头）

## 七、常见反模式（禁止）

| 反模式 | 正确做法 |
|--------|---------|
| 一个文件2000+行 | 按功能拆分为多个文件 |
| 一个函数100+行 | 拆分为子函数 |
| 全局变量满天飞 | 用 state.js 统一管理 |
| 直接操作 DOM | 用组件化方式 |
| 复制粘贴代码 | 抽取为公共函数/组件 |
| 硬编码 API URL | 用 api.js 统一封装 |
| 内联样式 | 用 CSS class |
| `!important` | 提高选择器优先级 |
| 空 catch 块 | 至少记录错误日志 |
| `alert()` | 用 toast/modal |
