### 0.2 依赖方向（严格单向）

```
clients → core → services/gpu → engine → api → server
```

- **core 层**：不依赖任何上层，纯逻辑
- **clients 层**：只依赖 core，封装外部服务调用
- **services/gpu 层**：依赖 core + clients，业务逻辑
- **engine 层**：依赖 core + services + gpu，调度核心
- **api 层**：依赖 engine + services，HTTP路由
- **server.py**：仅入口，组装所有模块

### 0.3 Registry 全局状态注册表

**文件**：`core/registry.py`

**设计目标**：所有跨模块共享状态集中管理，自动加锁消除竞态条件。

```python
from core.registry import registry

# 基础操作（线程安全）
registry.set("status_cache", {"data": None, "ts": 0})
cache = registry.get("status_cache", default={})
registry.delete("old_key")
assert registry.has("status_cache")

# 便捷方法
registry.update_dict("qos_state", level="warning")  # 原子更新字典
registry.append_list("events", event, max_len=100)  # 原子追加列表

# 复杂操作的专用锁
with registry.lock("queue"):
    tasks = registry.get("queue_tasks")
    tasks["new"] = {...}
    registry.set("queue_tasks", tasks)

# 调试快照
snapshot = registry.snapshot()
```

**已迁移的全局状态**（9个key）：

| Key | 原位置 | 类型 | 迁移方式 |
|-----|--------|------|---------|
| `status_cache` | services/status.py | dict | 直接迁移 |
| `last_scene` | services/scene.py | dict | 直接迁移 |
| `toast_enabled` | core/logger.py | bool | 直接迁移 |
| `toast_cooldown` | core/logger.py | dict | 直接迁移 |
| `last_busy` | engine/reaper.py | dict | 直接迁移 |
| `qos_state` | engine/qos.py | dict（含deque） | 引用保持 |
| `auto_protect_state` | engine/qos.py | dict（含deque） | 引用保持 |
| `lifecycle_state` | gpu/monitor.py | dict（4字段包装） | 状态包装 |
| `queue_state` | engine/queue.py | dict（3字段包装） | 状态包装 |

**迁移策略**：
1. **直接迁移**：简单变量，直接 registry.get/set
2. **引用保持**：含 deque 等可变对象，模块级变量指向 registry 中的同一对象，修改字段自动同步
3. **状态包装**：多个相关变量包装成一个 dict，模块级变量指向 dict 中的字段，需要重新赋值的变量通过 dict 字段修改

### 1.2 动态阈值公式

```python
# 替换所有硬编码的 16GB 阈值
class DynamicThresholds:
    def __init__(self, vram_total_gb: float, base_noise_gb: float):
        self.vram_total = vram_total_gb
        self.base_noise = base_noise_gb
        self.usable = vram_total_gb - base_noise_gb  # 实际可给 AI 负载

    @property
    def safe(self) -> float:      # 安全线，超过则告警
        return self.vram_total * 0.85

    @property
    def danger(self) -> float:    # 危险线，超过则自动释放
        return self.vram_total * 0.92

    @property
    def critical(self) -> float:  # 临界线，超过则强制释放+防死机
        return self.vram_total * 0.97

    @property
    def free_target(self) -> float:  # 生成前应释放到的剩余显存
        return max(2.0, self.vram_total * 0.15)
```

**示例**：
- 16GB 卡：safe=13.6G, danger=14.7G, critical=15.5G, free_target=2.4G
- 24GB 卡：safe=20.4G, danger=22.1G, critical=23.3G, free_target=3.6G
- 8GB 卡：safe=6.8G, danger=7.4G, critical=7.8G, free_target=2.0G

```python
def should_use_deep(decision: dict, context: dict) -> bool:
    if decision.get("needs_deep"):
        return True
    if decision.get("confidence", 1.0) < 0.7:
        return True
    if len(decision.get("plan", [])) >= 3:
        return True
    if decision.get("intent") == "multimodal_creation":
        return True
    if context.get("vram_free", 99) < 4.0:  # 显存紧张时需要更谨慎的规划

    return False
```

## 3. 多推理后端 Provider 实现

### 3.1 Provider 抽象接口

**文件**：`src/ceng/providers/base.py`

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class LLMResponse:
    content: str
    tool_calls: list[dict]
    prompt_tokens: int
    completion_tokens: int
    latency_ms: int
    model: str

class LLMProvider(ABC):
    name: str
    backend: str          # "local" / "cloud"
    vram_cost_gb: float   # 本地模型的显存占用，云端为 0
    speed_tier: str       # "fast" / "normal" / "slow"
    capability_tier: str  # "light" / "deep"

    @abstractmethod
    def chat(self, messages: list[dict], tools: list[dict],
             temperature: float = 0.2, max_tokens: int = 1024) -> LLMResponse:
        pass

    @abstractmethod
    def health_check(self) -> bool:
        pass
```

## 5. M-Eng 评测引擎实现

### 5.1 评测任务状态机

```
pending → queued → running → completed
                  ↓
                failed（可重试）
                  ↓
                interrupted（用户任务抢占，可恢复）
```

### 5.2 P0 基础指标评测脚本

**复用**：`scripts_global/model_bench_basic.ps1`（如不存在则新建）

```powershell
# 对指定 Ollama 模型，测试多档上下文的显存和速度
param($Model, $Contexts = @(16384, 65536, 131072))
foreach ($ctx in $Contexts) {
    # 1. 启动模型（ollama run with num_ctx=$ctx）
    # 2. 等待加载完成，记录 nvidia-smi 显存
    # 3. 发送 6K token 长输入，记录 prompt_eval_duration
    # 4. 生成 100 token，记录 eval_duration
    # 5. 计算 prefill tok/s 和 generation tok/s
```

### 6.1 ServiceAdapter 接口

**文件**：`src/peng/adapters/base.py`

```python
class ServiceAdapter(ABC):
    name: str

    @abstractmethod
    def detect(self) -> bool:
        """扫描常见端口+Docker容器名，发现服务实例"""

    @abstractmethod
    def get_vram_usage(self) -> float:
        """该服务当前显存占用（GB）"""

    @abstractmethod
    def free_vram(self) -> bool:
        """释放该服务的显存"""

    @abstractmethod
    def submit_task(self, workflow: dict) -> str:
        """提交生成任务，返回 task_id"""

    @abstractmethod
    def get_task_status(self, task_id: str) -> dict:
        """查询任务进度"""

    @abstractmethod
    def health_check(self) -> bool:
        """服务是否可用"""
```

### 10.2 错误链传播规范

**必须使用 aise ... from e 保留原始异常链：**

`python
# 正确示例（engine/queue.py _load_workflow）
def _load_workflow(workflow_name):
    p = os.path.join(BASE_DIR, "workflows", workflow_name)
    if not os.path.exists(p):
        return None
    try:
        with open(p, "r", encoding="utf-8-sig") as f:
            return json.load(f)
    except Exception as e:
        raise ConfigError("工作流模板解析失败: %s" % workflow_name,
                         detail={"file": p}) from e
`

**调用方捕获时可访问完整错误链：**

`python
try:
    wf = _load_workflow(task["workflow"])
except ConfigError as e:
    task["status"] = "failed"
    task["error"] = str(e)  # 包含原始异常信息
    # e.__cause__ 可访问原始异常
    return
`
