## 二、E9 日志脱敏决议（隐私边界，技术话题收官）

> E9 是"帮助改进（12.5 遥测）"的安全前置条件；也是统一日志（12.2）的隐私细化。四个决策点 Danny 已认可（"好。最后一个"）。

| # | 决议内容 | 状态 |
|---|---------|------|
| E9-1 | 日志只记元数据，不记用户内容（提示词 / 工作流 / 生成结果不入日志） | ✅ 已确认 |
| E9-2 | 路径 / 身份 / 密钥脱敏（路径归一化 + 身份打码 + REDACTED） | ✅ 已确认 |
| E9-3 | `sanitize()` 是写日志唯一出口，导出 / 上报前再跑一遍（双保险） | ✅ 已确认 |
| E9-4 | 遥测只取计数，反馈附带日志先脱敏 | ✅ 已确认 |

**E9 技术要点（落盘备份，实施时并入设计文档 §12.2/12.5）**：
- **核心原则**：GMae 日志记录"系统在做什么"（调度决策 / 资源变化），绝不记录"用户生成了什么"（提示词 / 图片内容）——顺带解决日志体积
- **脱敏动作**：
  - 路径归一化：`C:\Users\Danny\models\x.safetensors` → `%USERPROFILE%\models\x.safetensors`
  - 身份打码：机器名 / IP → `[HOST]` / `[IP]`
  - 密钥永不记明文：→ `[REDACTED]`
- **日志分级**：普通日志只记元数据（事件 / 操作 / 结果 / 耗时 / 显存）；详细调试日志（可选开）才记更多，但路径 / 身份仍脱敏
- **工程实现**：`sanitize()` 函数 = 路径归一化 + 敏感词替换 + 密钥屏蔽；所有日志写入必须经过它（唯一出口）；导出 / 上报 / 附带反馈前强制再跑一遍
- **与遥测衔接**：遥测只取普通日志的计数（事件类型计数），永不取详细日志；用户"提交反馈"可选附带日志 → 附带前必须过脱敏器；界面"导出日志"同样先脱敏

### A1 承诺边界 · 讨论稿（豆包观点，待确认）

- **承诺重新定位**："显存永不溢出" = 在 GMae 编排范围内，系统永远不会让显存溢出导致死机（非物理保证，是机制保证）
- **兜底阶梯**：
  1. 预算拦（事前）：任务提交即算账，`avail < 需求` → 拦截 + 告知差多少 GB
  2. QoS 降级（事中）：水位 RED → 对话自动降 9B→0.6B
  3. 强制拒绝 + 给选项：换量化 / 走云端 / 升级硬件
  4. 最坏情况：Windows 无 cgroup 靠轮询 + 主动卸载软护栏 + `--reserve-vram` 硬预留；兜底话术"绕过编排层硬塞超物理极限，任何软件都拦不住"
- **话术**："在你用 GMae 管理模型时，永不因显存而死机；超出物理极限的请求，会在加载前被明确拒绝并告诉你差多少。"
- **建议**：把"硬塞 52GB 被预算拦下并报差值"做成标准演示动作（比只演成功路径更可信）

### A2 信任问题 · 讨论稿（豆包观点，待确认）

- **铁律**：宁可漏报，不可误杀（误杀代价 >> 漏报）
- **后悔药五件套**：
  1. 验明正身：驱逐前比对完整路径 + 命令行参数，不只匹配进程名
  2. L2 白名单收窄：只对"可一键恢复的服务"（Fooocus/whisper 残留）自动杀
  3. 置信度降级：识别不确定时自动降为 warn 而非 kick
  4. 审计透明可回看：每个自动动作记录"为什么踢它"，前端可复盘
  5. 一键恢复：被踢服务一键 `docker start` + 恢复建议话术
- **建议**：配一个"审计面板"概念——所有自动决策可回看（做了什么 / 为什么 / 能不能恢复）

### B3 第一次体验 · 讨论稿（豆包观点，待确认）

- 冷启动链路：clone → 依赖 → 起服务 → 看到指挥台，每步都是流失点
- **一个命令起全套**：`start.bat` / `docker compose up`，依赖声明清楚（Windows + Docker Desktop + NVIDIA 驱动）
- **空状态设计**：fork 的人不一定有真实模型/GPU → 需要**模拟模式**（无 GPU 也能看到指挥台跑起来，虚拟显存数据）——同时服务"开源冷启动"和"大赛现场演示"
- **3 秒价值**：打开页面第一眼就看到显存条 + 场景按钮，不用读文档
- **0 star 阶段优先级**：README 截图（一眼看懂）> 演示视频（30 秒 wow）> 作品介绍文档
