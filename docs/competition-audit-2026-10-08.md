# GMae 竞赛竞争力审计（2026-10-08）

## 决策

**保留平台资产，重新设计调度控制核心。** 不建议全部推倒，也不建议继续以增加页面、模型数量和宣传指标为主。保留 Ollama/ComfyUI/Docker 适配器、原生 JS 界面、登记簿、事件系统、工作流及原始实验记录；将资源准入、释放验证、任务生命周期和参数化峰值模型作为新的核心。

审计基线：main `dc7f6a4a6bf6dd3d2ac5d830a9878bb610170bfd`；refactor/v2 `ec1130be516843f43c2e8641e6bf3851eb173a0c`。修复分支从后者派生，PR 面向 refactor/v2，避免将该分支约 240 个文件的既有重构直接合入 main。本次未运行用户机器上的模型、容器或看门狗。静态审计及离线回归不能替代真实 GPU 验收。

## 发现与处理

| 优先级 | 发现及影响 | 本次处理 / 剩余工作 |
|---|---|---|
| P0 | `.gitignore` 的 `_*` 隐藏全部包初始化文件；路由入口无法从干净仓库导入。两个测试有语法错误 | 恢复包文件、端点登记与语法；加入编译、导入检查 |
| P0 | 预算忽略当前驻留占用，已加载模型无条件放行，容量固定 16GB，释放估计可把不可能运行的任务算成可运行 | 使用实时单卡容量及占用，拒绝无效/过期遥测、未校准 context；分别计算直接运行与释放后峰值 |
| P0 | 队列释放后直接提交，不验证失败、忙碌服务或显存是否真正释放 | 提交前刷新预算，释放前检查忙碌，释放失败拒绝，释放后再次准入，检查取消请求 |
| P0 | 没有管理员时绕过全部鉴权；默认监听所有网卡；密码变更后的会话撤销未持久化 | 移除首次启动放行，默认回环监听，持久化撤销；离线安全回归 |
| P1 | Ollama `size` 被当作显存，十进制 GB 与 GiB 混用；桌面进程 MiB 被再乘 1024 | 使用 `size_vram`，统一内部 MiB/GiB；缺失遥测不伪造；修复单位转换 |
| P1 | 多处异常处理引用不存在的 `log_error`，掩盖原始异常 | 修复未定义名称；静态检查阻断新增未定义名称 |
| P1 | CI 只编译/导入，不运行测试；近期六次 CI 均失败；unittest 漏掉 pytest 函数测试 | 改为 pytest；迁移 33 个过时跳过测试；Windows/Linux × Python 3.10/3.12，另检查 JS 语法与本地导入 |
| P1 | 所有写路径没有共用原子资源预留；多个线程修改共享可变状态 | 尚未解决：需要唯一资源协调器及租约，所有加载/释放入口统一接入 |
| P1 | 排队任务仅驻内存；取消/超时不等于底层任务停止；无可靠重试与重启恢复 | 尚未解决：持久化状态机、适配器中断确认、幂等提交与恢复 |
| P1 | 紧急控制使用历史缓存可能误触发；Ollama 驻留被等同忙碌；其他场景/QoS/回收路径仍能绕过队列 | 尚未解决：区分驻留与执行，陈旧遥测禁用破坏性动作，统一写路径 |
| P2 | 安装入口 `cli.main` 无对应模块，Python 要求与实际语法不一致，环境和模型缺少锁定清单 | 独立修复安装链；比赛前必须在干净机器验证完整安装 |

预算仍是保守规则，不是训练得到的 OOM 预测器。已加载目标再次预留完整峰值，可能误拒绝缓存命中；当前更重视不把不安全请求放行，后续应拆分驻留、增量激活、KV cache 等阶段。释放成功与空闲仍有竞态，只有原子预留及统一入口才能进一步收敛。本次改动不支持宣称“绝不 OOM”。

### 架构与算法边界

现有分层有价值，但 services/engine 的交叉依赖和晚导入掩盖循环依赖；共享状态返回可变对象，读锁不保护后续修改。`/api/admission` 是建议接口，硬约束没有覆盖所有模型加载入口。旧 GateContext 还包含固定噪声/容量、Comfy 返回类型不匹配、context 固定值等问题，不应当作权威控制器。

ComfyUI 历史任务只能说明“最近使用”，不能证明模型仍驻留，更不能直接测量 CUDA allocator 碎片。当前 FIFO 加静态登记值可以叫预算调度，不能叫最优调度、自动 CPU offload 或模型级显存精确归因。当前遥测明确查询 GPU 0；多卡能力未实现或验证。

## 测试和验证

原 refactor/v2 的 unittest 发现 149 项，10 个错误、3 个跳过，并漏掉函数测试。修复启动基础后 pytest 为 206 通过、33 跳过；本次把这些过时跳过改成离线 API 合约及预算测试。初始调度回归 12 项中 11 项失败，证实缺陷而非仅改变断言。本地完整离线套件 270 项全部通过，零跳过（Python 3.11.9）；首次 268 项版本在独立干净检出也通过，且 Windows/Linux × Python 3.10/3.12 的远程 CI 全绿。最后补充两组非法峰值及负/非有限安全余量回归；最终提交的跨系统结果以 [PR #1](https://github.com/Dannywjw-Git/GMae-16GAS/pull/1) CI 为准。

真实环境脚本 `test_e2e_improvements.py`、`test_queue_e2e.py` 显式排除于离线发现，原因是访问实际服务或执行任务；不是已完成端到端测试。现有未使用导入等警告仍是技术债；未定义名称会阻断。前端检查覆盖 21 个 JS 文件的语法与相对导入，不覆盖浏览器交互、长任务重连和可访问性。

## 开源治理与合规

仓库有 MIT 许可和贡献文档，但第三方组件、镜像、模型和插件缺少完整版本/hash/许可清单。GMae 的 MIT 不自动覆盖模型权重或集成组件。

Open WebUI 不能概括为 MIT：当前版本采用含品牌要求的 [Open WebUI License](https://github.com/open-webui/open-webui/blob/main/LICENSE)，历史版本以对应版本许可为准。FLUX.1-dev 权重适用其[模型许可](https://huggingface.co/black-forest-labs/FLUX.1-dev/blob/main/LICENSE.md)，不能用“商业级画质”暗示商用权重授权。Docker Engine 与 Desktop 许可应分别核验，模型家族也不能代替具体制品许可。

发布前需要 dependency/model manifest、NOTICE、容器 digest、模型来源及 hash、漏洞报告政策、干净安装、tag/release 和贡献入口。公开运维材料包含个人环境/基础设施信息，需逐项最小化；本次未完成全面秘密扫描及所有代码来源追溯，不宣称全部合规。没有 release，不能用文档版本号代替可下载发布物。

## 竞赛定位

推荐定位：**单机 AI 工作站的混合负载显存预算与可解释任务编排**。聚焦中小团队一张卡轮转 LLM/图像/视频任务，回答“为何等待、释放什么、何时可执行、失败如何恢复”。[HAMi](https://github.com/Project-HAMi/HAMi) 已提供集群 GPU 共享/调度，不能将共享概念当创新；[Ollama](https://docs.ollama.com/faq) 已有模型加载、卸载和并发机制，应对比其真实默认行为。

[赛事官网](https://www.oschina.net/os2026/) 公布技术创新 30%、场景落地 30%、开源治理 20%、长期发展 20%，提交截止 2026-10-16 24:00，10-21 入围公布，10-29 决赛。FAQ 飞书页面未成功读取，本报告以官网为依据。用户已确认报名为智算云自主选题；仓库历史材料提到 ZSvirt 企业命题，应在新参赛摘要中去除该关联。当前项目无需包装为完整虚拟化/网络/IO/根因分析体系。

竞争力的关键是可解释准入、真实对照实验、可靠恢复和可贡献的开源交付，不是增加生成模型数量。路线见 [整改路线](competition-remediation-roadmap-2026-10-08.md)。
