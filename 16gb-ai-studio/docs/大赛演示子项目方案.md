## 一、子项目定位

**目标**：产出 5 分钟完整版 + 3 分钟展示版演示视频，配套截图/GIF/文字说明，把 GMae 作为"消费级显卡显存编排专家"的核心能力演出来。

**核心叙事**：GMae 不是"16GB 卡的工具"，而是"8G~48G 全系列消费级显卡的显存编排层"。16GAS 只是入门级参考实现，用最低配证明能力。

**差异化卖点**：
- 预演模式（What-if）—— 竞品对比中 GMae 独有
- 换卡自动适配 —— 动态预算引擎，8G/16G/24G/48G 自动调整
- 单卡全模态 —— 对话+出图+视频+音乐在一块消费级卡上错峰运行

## 三、5 分钟完整版故事线

### 开场（0:00-0:15，15 秒）
- 黑屏 → GMae Logo + 标语「One GPU, Infinite Models」
- 副标题：「消费级 AI 服务器的显存编排专家 | 支持 8G~48G 全系列消费级显卡」
- 一句话旁白（字幕）："一块消费级显卡，管理无限 AI 模型——对话、出图、视频、音乐，全模态编排。"

### 第一幕：消费级显卡的痛点（0:15-0:45，30 秒）
- 快速闪切 4 个场景：
  - 8GB 卡：跑 Flux 直接 OOM，弹窗"显存不足"
  - 16GB 卡：同时开对话+出图，卡顿死机
  - 24GB 卡：用户手动管理，不知道怎么充分利用
  - 48GB 卡：专业卡太贵，消费级没有编排工具
- 字幕："消费级显卡（8G~48G）没有专业的显存编排层——大厂只做云GPU，不管消费级"
- 转场：GMae 界面打开，**显卡型号自动识别**（显示"RTX 4060 8GB"），显存能量条按实际总量自适应

### 第二幕：换卡自动适配（核心差异化，0:45-1:30，45 秒）⭐
- 三分屏对比（或动画演示）：同一份 GMae 代码在三种配置下的表现
  - **8GB 卡**（左）：预算引擎自动收紧，只允许轻量模型（0.6B 对话 + SDXL 出图）。预演模式选 Flux → 明确标记「⛔ 不可行，差 4GB，建议升级显卡或用 SDXL」
  - **16GB 卡**（中，当前真机）：对话 9B + Flux 出图 + Wan2.2 视频错峰运行。预演模式选 Flux → 显示「将释放 Fooocus、对话降级 0.6B」
  - **24GB/48GB 卡**（右）：预算引擎自动放宽，可同时跑对话 + Flux + 视频。预演模式选 Flux → 显示「✅ 显存充足，无需释放，预计 1.5 分钟」
- 字幕："动态预算引擎——显存总量从 nvidia-smi 实时读取，阈值按比例自适应，换卡不用改一行代码"
- 底部标注："8G/24G/48G 为模拟演示，16G 为真机实录"

### 第三幕：预演模式（杀手锏，1:30-2:30，60 秒）⭐
- （16GB 真机实录）
- 当前状态：Fooocus 占 8GB + 对话 9B 占 5GB + 剩余 3GB
- 用户点「预演模式」→ 弹出预演窗口
- 模型列表：每个模型显示「✅ 可跑 / ⏳ 需释放 X GB / ⛔ 差 Y GB」
- 选择"Flux 高质量出图" → 右侧显示预演详情：
  - 📊 当前显存：3GB 可用 / Flux 需 8.2GB
  - 📋 释放计划：释放 Fooocus（+8GB）、对话降级 9B→0.6B（+4GB）
  - ⏱️ 预计时间：释放 3 秒 + 生成 2 分钟（基于历史生成时间统计）
  - ⚠️ 影响：Fooocus 任务将中断、对话响应暂时变慢
  - ✅ 确认执行 / ❌ 取消
- 点「确认执行」→ 状态播报横幅："正在为 Flux 腾出 12GB，对话暂时降级…" → 3 秒后显存释放 → Flux 开始生成 → 进度条实时更新
- 字幕："先看谱再指挥——调度决策显性化，用户永远有否决权。竞品对比：GMae 是唯一有预演模式（What-if）的开源项目"

### 第四幕：多模态编排 + 门卫 + QoS（2:30-3:15，45 秒）
- **多模态编排**（20 秒）：16GB 卡连续跑 出图（Flux）→ 视频（Wan2.2）→ 音乐（Music3），每个任务开始前都有预演确认（快进展示），全程自动腾挪，无手动切换，不死机
- **门卫**（15 秒）：启动一个未登记进程（如另一个 ollama 实例）→ 调度中心 3 秒内检测 → 警告横幅「⚠️ 检测到未登记进程 llama-server PID 1234，占 2GB，点击驱逐」→ 点驱逐 → 进程被 kill，显存释放
- **QoS**（10 秒）：Flux 顶格生成时发消息 → 对话自动降级 0.6B + 通知「服务正忙，Flux 完成后恢复 9B」→ Flux 完成后自动恢复 9B
- 字幕："单卡全模态，专家工作流。准入制门卫 + 主动编排，安全与体验兼顾"

### 第五幕：开源可复现 + 扩展性（3:15-3:35，20 秒）
- **扫描器加新模型**（10 秒）：把一个新模型文件放进 ComfyUI 模型目录 → 点「扫描模型」→ 扫描器发现新模型 → 显示「未登记：darkidol-8b，文生图，约 4GB」→ 点「一键登记」→ 模型登记台自动出现，预演模式里也能选了
- **开源可复现**（10 秒）：展示 GitHub 仓库页面 + Docker Compose 一键部署命令 + 文档入口
- 字幕："配置驱动 + 模型登记台 + 开源可复现。加模型/换显卡/加工作流只改配置，不用改代码"

### 结尾（3:35-3:50，15 秒）
- 成果展示墙：生成的图/视频/音乐缩略图网格（4×3）
- GMae Logo + 标语「One GPU, Infinite Models」
- 信息：「GPU Maestro-显存指挥家 | 2026 上海开源软件应用创新大赛 · 智算云赛道 | 支持 8G~48G 全系列消费级显卡」
- 开源地址：GitHub 链接（二维码）
- 淡出黑屏

> **注**：5 分钟完整版实际约 3:50，预留 1:10 缓冲（某些环节可能延长，或加过渡画面）。最终以实际录制为准。

## 五、预演模式功能完善清单

当前预演模式已有基础 UI（2026-08-29 重构完成），演示级功能需完善：

| # | 功能 | 现状 | 实施方案 | 优先级 |
|---|------|------|---------|--------|
| 1 | 释放清单明细 | ⚠️ 只显示差多少 GB | 明确列出"将释放什么模型/降级什么/释放多少 GB"，从预算引擎获取 | 高 |
| 2 | 预计时间 | ❌ 无 | 按历史生成时间统计：首次运行用模型大小估算，后续记录实际生成时间取均值 | 高 |
| 3 | 确认执行衔接 | ⚠️ 有确认按钮但未真正提交任务 | 确认后调用任务队列 API（/api/queue），真正提交生成任务 | 高 |
| 4 | 一键演示模式 | ❌ 无 | 预设演示场景（Fooocus+9B 对话占满显存），一键进入"演示状态"，方便反复录制 | 高 |
| 5 | 影响提示 | ❌ 无 | 显示"Fooocus 任务将中断、对话响应暂时变慢"等用户影响 | 中 |
| 6 | 状态播报文案 | ✅ 已有 | 演示时优化文案，更戏剧化 | 中 |
| 7 | 预演历史 | ❌ 无 | 可选：记录最近 N 次预演决策 | 低 |

### 预计时间统计方案
- 数据结构：`generation_stats.json`，按模型名记录 `{count, total_seconds, avg_seconds}`
- 首次运行：无统计数据时，按模型文件大小 × 系数估算（如 Flux Q5 约 6GB → 估算 120 秒）
- 每次任务完成：更新统计（count+1, total_seconds+=实际耗时, avg_seconds=total/count）
- 预演模式显示：`基于 N 次历史生成，平均约 X 分钟`（有统计时）或 `首次运行，估算约 X 分钟`（无统计时）

## 六、一键演示模式设计

**功能**：预设一个"演示就绪"状态，一键进入，方便反复录制。

**预设场景**：
- 启动 Fooocus 容器（或确保在跑）
- 加载 qwen3.5:9b 对话模型（docker exec ollama run qwen3.5:9b）
- 确保 ComfyUI 未运行（或已 /free）
- 目标显存状态：Fooocus 占 ~8GB + 9B 占 ~5GB + 剩余 ~3GB（正好是预演 Flux 会"差 5GB"的戏剧冲突状态）

**实现**：
- 后端 API：`POST /api/demo/setup`（一键准备演示环境）+ `POST /api/demo/reset`（恢复正常状态）
- 前端：第三层设置里加一个「🎬 演示模式」按钮，点击后确认 → 自动执行预设场景
- 安全：只在用户明确点击时执行，不自动触发；执行前显示"将启动 Fooocus + 加载 9B，预计 10 秒"
