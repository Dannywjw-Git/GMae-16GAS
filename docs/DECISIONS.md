## 独立评审建议

D022：不以 history basename 改名或“loaded=零峰值”修复重复卸载。真实驻留试验仍增长 672/1,536 MiB；下一阶段采用可选、只读的后端 LoadedModel/ModelPatcher 驻留来源观察及分阶段预算。缺失接口、未知来源、部分卸载、实例改变或活动竞争不能采用 warm 准入。这是设计，尚未实现；不替代真实策略对照和混合负载验收，详见 [设计](phase-profile-design.md)。

D021：先建立显式卸载后低 torch/物理容量已核验与保留驻留两种校准条件。512/768 两组四次真实生成成功，公开原始数据和按配置/环境分组的独立分析；采样器均未缓存。生成窗口不含身份核验和卸载，不与 PR #9 端到端直接比较，不宣传 GMae 加速。各条件只有一次、CPU/磁盘缓存未控制，驻留模型身份仍未证明。

D020：真实 seed 45 试验表明释放命令完成与物理显存回收存在延迟。持续读取实际容量，允许等待中暂时拒绝，30 秒超时仍保留未知；任务终态不能替代资源操作结束证据。本次失败不改写为成功，仅凭特定拥有者、未提交、回执及 fresh 后端/GPU 证据做人工核验。下一步优先减少多余卸载，不扩展通用恢复框架。

D019：正式准入从安装的原始字节重新计算包络并固定 raw 摘要、margin 和实际工作流；执行前 fresh 身份核验。seed/noise_seed/输出名不影响配置匹配，其他输入包括提示词保守绑定。只支持当前受测原生 SDXL 配置，包络不能当作统计 OOM 保证。seed 46 真实队列验证通过；143.5 秒暴露摘要核验和加载瓶颈，不能宣传调度加速。详见测量准入报告。

D018：使用不同 seed 排除采样器缓存命中，记录实际服务环境、模型摘要与启动配置摘要，区分加载条件与调度收益。只有身份完整、样本与峰值一致的原始证据可以构建 Profile 原型；采用整卡观测峰值加明确工程余量，不宣称统计保证。单次驻留 Profile 暂不启用正式准入，正式接入与参数网格/混合负载对照是下一阶段重点。

D017：在测量 Profile 接入之前，资源参数偏离模板时拒绝复用固定预算，默认模板估计仍标记未验证。使用受控、显式启动的 SDXL 小规模基线打通真实采样；公开原始样本、复现条件及限制，不把一次成功、采样峰值或整卡占用变成性能/安全保证。运行中服务与 shell 的 PyTorch 存在差异，采用服务实际报告环境。后续必须补模型摘要与重复对照后才能发布性能结论。

D016：接受用户转述的 PR #4 独立评审优先级。采用服务器整个进程生命周期的系统锁，保护同账户不同端口与检出；锁恢复后强制沿用原账本，不能用新数据库绕过未知执行。容器成功回执必须加 fresh inspect 目标状态证据，仍不证明 GPU 空闲。完成这两处验收缺口后立即回到参数化 Profile 与真实实验；不扩展通用恢复框架。跨账户和外部客户端隔离尚未解决，保留明确限制，不夸大为整机任意进程 GPU 隔离。

D015：入队时固定实际后端工作流和摘要，不能在执行时重新解释新任务的模板。旧任务在准入前固定一次；参数无法绑定时拒绝，取消先于模板读取。同一幂等键在模板改变后产生不同 payload 时明确冲突。当前注册表显存估计必须标注未验证，测量准入接入是下一项必做工作。

D014：先以完整实际工作流摘要与执行环境精确匹配绑定测量样本，不对分辨率、批量等参数外推。预算采用观测最大值加显式余量，不宣传 OOM 保证。来源字段检查不等于认证原始测量；原始数据核验与正式准入接入仍待完成，测试夹具不作为性能证据。

当前尚无已接收、可引用的 Chat Agent 独立评审意见。后续每条意见补充来源 PR/评论或公开文档链接、适用提交、复核证据和处置结论；有冲突时明确记录理由。

D023：真实安装暴露缺少启动峰值校准，保留生产重启拒绝，不用生成峰值代替启动证据，不以其他操作名称绕过准入。只读驻留观察仍需实际部署验收；先执行生产准入预检，再复制及本地备份。启动校准须明确实验协议和原始数据，warm 准入保持关闭。
