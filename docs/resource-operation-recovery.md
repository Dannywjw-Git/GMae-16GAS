# 资源操作的持久保护

范围：正式服务器启动后，所有经过统一协调器的资源操作。操作日志与任务账本共用 `GMAE_TASK_DB`（默认 `data/tasks.sqlite3`），本地数据不入 Git。

协调器在首次进入 running/releasing/stopping 阶段前保存操作意图，包含操作、服务、模型和所有者，不保存提示词。准入中的模型释放同样记录。仅做预检且未触发资源变更的拒绝不产生待恢复操作。嵌套适配器共用外层日志，不重复占有资源。

适配器返回且明确进入 completed/failed 后保存结束记录；异常或无法保存结束记录时，日志及当前资源预留均保持未知。下一次正式启动先恢复操作日志，再恢复任务队列，随后才启动后台资源操作和 HTTP 服务。未知操作不自动重放。

生成操作与任务账本关联：已提交且状态未知的任务以其持久关联 ID 恢复一个预留，同时绑定操作日志；核验先保存任务和操作日志的终态，再解除预留。两份终态写入不是同一事务，重复核验允许匹配的任务终态，避免部分保存失败后无法重试。

## 命令尝试与回执

资源变更阶段的外部命令增加独立尝试 ID，在启动进程前保存所属操作及参数。返回码为 0 且回执成功保存后，该命令才确认完成。超时、非零退出或回执保存失败都保留未知状态；外层不能把它重新解释为普通失败并释放预留。PowerShell 脚本共用此边界。Docker ps/inspect 等只读查询不记录为资源变更。

尝试 ID 是本地关联身份，不是 Docker daemon 的执行 ID。当前主进程仍负责写回执，主进程退出后回执可能缺失；独立执行者持续写回执的能力尚未实现，不能声称命令已能自动恢复。参数可能包含本机路径和运行信息，只存放在已排除出 Git 的本地数据库，不能公开数据库作为竞赛证据。

## 验证与当前限制

完整离线套件 380 项通过。新增 8 项操作日志测试及 1 项队列联合恢复测试，覆盖请求前落盘、存储失败禁止适配器、结束保存失败保留预留、无变更的准入拒绝、准入释放异常、嵌套操作、外层异常和适配器进入后子进程退出。

命令回执接入后完整套件增至 388 项通过，新增 8 项验证请求前落盘、禁止未落盘命令、真实受控子进程超时、回执写入失败、禁止带未知命令确认操作、只读查询区分和非零退出。真实 Docker/Ollama 故障仍未验证。

这些不是实际 Docker/Ollama 崩溃或 GPU 实验。没有后端任务 ID 的手动操作目前恢复为阻挡，但尚无完整自动核验解除路径；不能仅根据进程重启、低显存或空队列推断原命令已结束。该路径必须补齐可信适配器证据，不能通过清空数据库绕过。跨进程/跨端口 GPU 排他尚未实现。

操作日志在正式服务器启动时启用。仅导入模块并单独调用适配器的外部脚本，必须调用 `restore_resource_operations()` 完成初始化；离线测试使用隔离账本。未启用日志的第三方调用不属于此持久恢复保证。
