## 二、新发现的问题（本次复核重点）

### 🔴 N1：双轨目录结构——公开仓库存在两套代码与两份文档

git 仓库（`GMae_Amanda` 根）**同时跟踪两套互不同步的内容**：

| 位置 | server.py | registry.json | docs | 定性 |
|---|---|---|---|---|
| `vram-console/`（根，扁平） | **26 KB（旧版）**，无 QoS/WebSocket/认证系统 | 21,276 B | 根 docs/（旧） | 2fc60a1 公开版时代的旧结构 |
| `16gb-ai-studio/vram-console/`（子目录） | **120 KB（新版）**，含 auth/QoS/WebSocket/登记台 | 21,190 B | 16gb docs/（新） | 08-28 切割后的独立推进产物 |

- 两套 `server.py` 体积差 **4.5 倍**，功能差异巨大（旧版无 qos_enforce / WebSocket / auth.py 集成）
- 两份 `registry.json` 内容不一致（长度差 86 B）
- 根 `docs/` 与 `16gb-ai-studio/docs/` 是**两套完全不同的文档**（根：总纲/运营蓝图/定稿决议；子：开发日志/进度跟踪/第二阶段方案/观察报告）
- **后果**：评审 clone 公开仓库后无法判断主版本，README 未说明目录关系；这是公开前的**结构灾难级**问题，直接损害"可复现性 + 开源治理"两个评审维度

### 🔴 N2：大量代码变更未提交（"已提交"声称与实际不符）

`git status` 显示 **10 个文件、+2625 / -785 行未提交**，含核心文件：

- `index.html` **+1756 行**（08-30 上午的 Immich 风格 UI 全面重构，完全未入库）
- `server.py` +42 行、`watchdog.py` +45 行、`WATCHDOGS.md` +13、`stop.bat` +15
- `tests/test_registry.py` +287 行（测试扩充）
- 根 `vram-console/resources/registry.json` +613 行

工作交接/执行方案称"第二阶段优化已提交（a53c4ff）"，但**提交之后又有整批代码改动未 commit**。后果：当前运行的代码与 git 主分支不一致，一旦误操作即丢失整批成果；评审看到的版本落后于实际功能。

### 🟡 N3：`.gitignore` 残留未解决的 merge 冲突

`.gitignore` 内容含 `<<<<<<< HEAD` / `=======` / `>>>>>>> b3a909c...` 冲突标记，且中文注释为乱码（GBK 编码问题）。冲突未解析导致规则拼接混乱，`users.json` 等敏感文件的排除可能不按预期生效。这是版本控制管理上的明显瑕疵。

### 🟡 N4：测试入口与测试文件不同步

`tests/` 目录有 5 个测试文件（registry/auth/api_contract/**budget/security**），但 `run_tests.py` 的 `TEST_MODULES` 只收录前 3 个。**`test_budget.py`、`test_security.py` 是未跟踪的新文件，从未被运行过**——预算引擎和安全管理这两个核心模块实际上没有自动化测试兜底，与"74 测试全绿"的宣传不完全相符（实测 81 个通过的是已收录的 3 模块）。

### 🟡 N5：认证系统把"简单场景"复杂化了（设计权衡，供参考）

Token 认证（轻量、适合脚本/自动化）被替换为 邮件+密码+Session+SMTP 验证码 体系（auth.py 约 400 行 + 7 个 API + 登录页）。功能完备、测试覆盖好（32 个 auth 测试）。但对一个"家庭内网调度中心"而言，**复杂度与威胁模型不匹配**：单用户本地工具引入账号体系、忘记密码、验证码邮件，运维成本上升（工作交接已记录"忘记密码/修改密码待实测"）。保留 API Token 为向后兼容是对的，但建议明确"默认关闭账号体系、Token 为主"的部署模式，避免评审误判为过度设计。
