## 一、测试结论

**大部分按钮功能正常**。用户反馈"好多不能用"的核心原因是：
1. 一键释放 / 启动 Helper 此前确实因后端 bug 完全失效（已在本轮修复）
2. 停止 Helper 后按钮状态不刷新，用户误以为没生效
3. 门卫"重新检查"按钮无视觉反馈，用户误以为没点到

**真正存在的前端缺陷共 2 个（均为 P1）**，详见下文。

## 三、发现的缺陷

### BUG-019（P1）：停止 Helper 后按钮状态不更新

- **页面**：显存账本
- **现象**：点击"停止 Helper"后，API 返回 ok（Helper 实际已停止），但按钮文本仍显示"停止 Helper"，不会变为"启动 Helper"
- **根因**：停止后调用了 refresh()，但 refresh 可能未重新渲染 Helper 卡片，或 helper_running 状态未更新
- **影响**：用户以为停止失败，反复点击
- **修复建议**：停止/启动 Helper 成功后，立即更新 helper_running 状态并重新渲染卡片

### BUG-020（P1）：门卫"重新检查"按钮无视觉反馈

- **页面**：门卫
- **现象**：点击"重新检查"后，页面无任何变化（无 loading、无 toast、时间戳不更新），用户误以为按钮坏了
- **根因**：refresh() 函数仅更新 store 中的 status，renderAll 会重新渲染，但因数据未变化，DOM 无明显差异；且页面有 10s 自动轮询，手动刷新与轮询无法区分
- **影响**：用户体验差，以为按钮不能用
- **修复建议**：点击后显示"检查中…"loading 状态，完成后显示 toast"已重新检查"，并强制更新时间戳

### 其他观察（非缺陷）

- 控制台有多个 `ERR_CONNECTION_REFUSED`，是 ComfyUI WebSocket 连接失败（ComfyUI 容器未运行），不影响 GMae 核心功能
- 模型页分类筛选为纯前端逻辑，不发请求，属正常设计

### 6.2 共性问题总结

**共性问题1（核心）：刷新类按钮普遍无任何视觉反馈**
- 涉及 5 个页面：门卫"重新检查"、账本"刷新"、队列"刷新"、日志"刷新"、模型"刷新"
- 表现：点击后无 loading、无 toast、无视觉变化，用户以为按钮坏了
- 根因：各页面刷新按钮直接绑定 `refresh` 函数，未封装统一的操作反馈

**共性问题2：Helper 停止功能后端 bug + 前端状态不同步**
- 后端 bug：`_helper_kill_processes()` 和 `_helper_process_count()` 中 PowerShell 匹配模式为 `vram-helper`（连字符），但实际启动的脚本是 `vram_helper.py`（下划线），导致永远匹配不到进程，Helper 无法被真正停止
- 前端问题：Helper 启停后依赖 `refresh()` 重新渲染，但 status 缓存可能未更新，且 vram.js 未订阅 store 变化，导致按钮状态不更新

### 6.3 统一修复内容

#### 修复1：5 个页面刷新按钮统一加 loading + toast

| 文件 | 按钮 | 修改内容 |
|------|------|---------|
| guard.js | 重新检查 | 点击后 btn.disabled=true, 文本变"检查中…"，完成后 toast"门卫已重新检查" |
| vram.js | 刷新 | 点击后 btn.disabled=true, 文本变"刷新中…"，完成后 toast"显存数据已刷新" |
| queue.js | 刷新 | 点击后 btn.disabled=true, 文本变"刷新中…"，完成后 toast"队列已刷新" |
| logs.js | 刷新 | 点击后 btn.disabled=true, 文本变"刷新中…"，完成后 toast"日志已刷新" |
| models.js | 刷新 | 点击后 btn.disabled=true, 文本变"刷新中…"，完成后 toast"模型列表已刷新" |

#### 修复2：后端 Helper 进程匹配模式修正

- 文件：`services/helper.py`
- 修改：`_helper_process_count()` 和 `_helper_kill_processes()` 中的 PowerShell 匹配模式从 `vram-helper` 改为 `vram[_-]helper`（同时匹配下划线和连字符）
- 效果：Helper 停止 API 现在能真正杀死进程，`/api/status` 返回的 `helper_running` 正确变为 false

#### 修复3：前端 Helper 启停后直接更新 DOM

- 文件：`web/js/pages/vram.js`
- 修改：Helper 启停成功后，直接更新 DOM（状态标签文本+class、按钮文本+data-helper 属性），并同步更新 store；不立即调用 refresh()（避免 status 缓存未更新导致重新渲染覆盖 DOM 变化），等 15 秒轮询自动刷新
- 效果：点击停止后立即显示"未运行"+"启动 Helper"，无需等待
