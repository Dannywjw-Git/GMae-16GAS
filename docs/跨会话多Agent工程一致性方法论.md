# 跨会话 / 多 Agent 工程一致性方法论（防漂移手册）

> 创建：2026-09-03
> 目的：解决多 Agent（豆包/WorkBuddy/DSH）轮换、长上下文下的"写后忘前、重复开发、信息遗漏、方案漂移"。
> 适用：所有参与 GMae 的 Agent，开工前必读，收工时按本手册更新记忆。
> 社区依据：AGENTS.md 跨工具标准、Cline Memory Bank、Claude Code 记忆分层、codebase-memory-mcp、Handoff Protocol（2026 年行业共识）。

---

## 0. 核心原理：Agent 每次会话都"失忆"

大模型没有跨会话记忆，上下文窗口有限且会被压缩。稳定性不来自模型"记住"，而来自**外部化、结构化、单一事实源**的工程文件。判断一套记忆体系好不好，就看：新 Agent 能否在 5 分钟内无歧义接手，且不重复劳动、不推翻已定方案。

---

## 1. 四层记忆栈（GMae 标准）

| 层 | 载体 | 内容性质 | 更新频率 | 长度约束 |
|----|------|---------|---------|---------|
| ① 静态规则 | AGENTS.md（根 + 16gas） | 铁律、架构、禁令、必读清单 | 极少改 | 单文件 ≤200 行 |
| ② 过程知识 | .user_skills/*/SKILL.md | 某类任务怎么做（可复用流程） | 按需增补 | 每个 Skill 聚焦单一能力 |
| ③ 动态状态 | 工作交接/进度/决策/Open Issues | 当前焦点、进度、决策、问题 | 每次收工更新 | 单文件 ≤200 行 |
| ④ 外部大脑 | codebase-memory-mcp（规划） | 代码知识图谱、调用关系 | 后台自动同步 | 按需查询 |

**铁律：静态规则与动态状态分离。** 易变的进度绝不写进 AGENTS.md；稳定的铁律绝不散落在日志里。

---

## 2. 动态状态层标准结构（重点整改对象）

### 2.1 工作交接.md = activeContext，固定四段式

```markdown
# 工作交接
## 一、当前焦点（不超过 5 条，每条一行）
- 正在做：[任务] —— 进展到哪 / 卡在哪
## 二、下一步（明确的待办，原子化，单一交付物）
- [ ] xxx（对应文件：路径）
## 三、活跃问题 Open Issues（未关闭的坑，防止遗忘）
- [问题] —— 现状 —— 暂定方案/搁置原因
## 四、最近变更（只留最近 10 条，旧的进开发日志）
- 日期：改了什么文件、为什么、验证结果
```
- 用**清单**，不用大段叙述（旧版"当前在做什么"一大坨是反模式）。
- 每个任务原子化："重写 topology.js 容器折叠"合格；"改前端"不合格。

### 2.2 决策记录.md（ADR，新增）

每个重要决策一条，防止后续 Agent 推翻或重复讨论：
```markdown
## ADR-001 蓝图禁止擅改
- 决定：调度中心架构蓝图修改必须经主公批准
- 原因：设计权威，避免 Agent 顺手改导致不一致
- 否决方案：允许 Agent 自行修正蓝图
- 日期/提出者
```
适用：架构选型、技术栈、禁令、被否决的方案、用户拍板的结论。

### 2.3 开发日志瘦身规则
- **主文件只保留最近 2 周**，历史按月归档到 `docs/devlog_archive/开发日志_YYYYMM.md`。
- 主文件任何时候不超过 ~400 行；超过就归档。
- 目标：Agent 读日志只看近期，需要历史细节时再按时间去归档里 grep。

### 2.4 项目进度跟踪.md
- 保持任务清单 + 状态（未开始/进行中/已完成/搁置），是"谁做了什么"的单一事实源。
- 接近 200 行时，把已完成的旧任务挪到归档。

## 3. 多 Agent 协作：防重复与交接协议

### 3.1 任务拥有权（任务锁）
- 工作交接顶部维护"**当前任务拥有者**"字段：`[拥有者:豆包] [任务:xxx] [开始时间]`。
- Agent 开工前先看：若有其他 Agent 正持有相关任务，不重复开工；收工时释放（写"无"）。
- 同一文件同一时间只允许一个 Agent 修改。

### 3.2 标准交接五要素（Handoff）
每次收工/换人，交接包必须包含：
1. **上下文转移**：当前焦点 + 已改文件清单 + 未完成项
2. **状态可查**：进度跟踪/任务锁已更新到最新
3. **验证结果**：改了什么、怎么验证的、结果（语法/测试/页面）
4. **遗留与回退**：已知问题、失败尝试、回退方法
5. **留痕**：开发日志 + 决策记录已写

### 3.3 防重复开发三策略
1. 单一事实源：任务状态只看进度跟踪，不凭记忆判断"做没做"。
2. 能力路由 + 任务锁：按模块分工，认领后再动手。
3. 动手前先检索：用 grep / 代码图谱确认是否已有实现，再决定写新代码。

## 4. 外部大脑：代码知识图谱（P1 引入）

### 选型：codebase-memory-mcp
- 单二进制、零依赖、本地 SQLite，支持 Python/JS，后台监听文件自动同步。
- 能力：函数/类/调用关系/路由图谱；"谁调用 X""改 X 影响什么"；死代码检测。
- 收益：结构查询 ~500 token 替代逐文件读 ~80K token（省约 120 倍），根治"找不到已有实现→重复开发"。
- 备选：lxDIG-MCP / remembrallmcp（额外支持相似代码查重、持久决策记忆）。

### 使用约定
- 三个 Agent 连接同一个本地图谱实例，索引目录指向 `16gb-ai-studio/vram-console`。
- 改完代码后依赖其 watcher 自动重建；跨会话先查图谱再动手。

## 5. Agent 开工 / 收工 SOP

### 开工（每个新会话）
1. 读 AGENTS.md（根→16gas）必读清单。
2. 读 工作交接.md（当前焦点/下一步/Open Issues/任务拥有者）。
3. 需要历史再读 进度跟踪、决策记录、近期开发日志（不一次性全读）。
4. 动手前 grep / 查代码图谱，确认无重复实现。
5. 认领任务：更新任务拥有者字段。

### 收工（主公铁律五步 + 本手册要求）
1. 更新开发日志（只追加近期，超量归档）。
2. 更新进度跟踪与工作交接（四段式，释放任务锁）。
3. 更新技术细节/参考脚本。
4. 核查与 LLM 进化指南/最高指南差异。
5. 上传 Git/Gitee（排除敏感与大文件）。
+ 有重要决策时追加一条 ADR；关闭的 Open Issue 标记结果。

## 7. 反模式清单（出现即纠正）
- 把易变进度写进 AGENTS.md，导致铁律文件频繁变动、越来越长。
- 用一大段自然语言描述当前状态（应改为清单）。
- 不检索就新写功能，结果重复已有实现。
- 全量读取 134KB 开发日志（应只读近期 + 按需 grep 归档）。
- 改完后端不重启验证就宣称完成。
- 多个 Agent 同时改同一文件、无任务锁。
- 做了决策不留 ADR，下个会话重新讨论一遍。
