# AI 模型综合评估套件 (Model Benchmark Suite)

> 跨模态统一评估框架：LLM / 图像生成 / 视频生成 / 音频生成。
> 专为 **16GB 消费级显卡** 优化，突出低显存性价比与量化损失分析。
> 配套自动化脚本，评估从"手动30分钟"降到"脚本5分钟"。

## 何时使用

- ✅ 新模型到手，需要和已有模型横向对比
- ✅ 同一模型不同量化版本的效果/速度/显存对比（量化损失曲线）
- ✅ 参赛作品需要客观的模型评测数据
- ✅ 判断某个模型能否在 16GB 显卡上运行
- ✅ 定期复测，跟踪模型迭代效果
- ❌ 单次随意生成（不需要走完整评估流程）

## 一、快速开始（自动化脚本）

> 脚本位于 `scripts/` 目录，优先使用脚本而非手动操作。

### 1.1 图像生成批量评估

```bash
# SDXL 跑全部标准 Prompt（含中文文字渲染测试）
python scripts/comfyui_batch_run.py --model sdxl --output ./results/sdxl_20260827

# Flux 只跑3条核心 Prompt（快速模式）
python scripts/comfyui_batch_run.py --model flux --prompts IMG-01,IMG-02C,IMG-05 --output ./results/flux_quick

# 自定义参数
python scripts/comfyui_batch_run.py --model sdxl --steps 30 --cfg 7 --width 1280 --height 720 --seed 42
```

脚本自动完成：提交工作流 → 0.5s 间隔显存采样 → 记录耗时 → 下载输出 → 汇总 JSON。

### 1.2 LLM 批量评估

```bash
# 完整评估（8题，含自动评分）
python scripts/ollama_batch_eval.py --model qwen3.5:9b --output ./results/llm_qwen9b

# 快速模式（3道核心题：推理/指令遵循/数学）
python scripts/ollama_batch_eval.py --model qwen3.5:9b --quick

# 指定测试题
python scripts/ollama_batch_eval.py --model qwen3:0.6b --tests LLM-01,LLM-06
```

自动评分覆盖：推理关键词、代码可运行性、数值答案验证、长度约束检查。

### 1.3 独立显存监控

```bash
# 监控某个进程的显存峰值（进程结束自动停止）
python scripts/vram_monitor.py --pid 12345 --interval 0.5

# 监控指定时长
python scripts/vram_monitor.py --duration 120 --output vram_result.json --json
```

## 二、评估流程（两档）

### 2.1 快速评估（5分钟，3条核心Prompt）

适合"新模型到手先扫一眼"。

| 模态 | 核心测试项 |
|------|-----------|
| 图像 | IMG-01（写实人像）+ IMG-02C（中文文字渲染）+ IMG-05（科幻场景） |
| 视频 | VID-01（人物运动）+ VID-04（城市动态）+ VID-07（科幻动态） |
| 音频 | AUD-01（电子音乐）+ AUD-02（钢琴）+ AUD-05（电影配乐） |
| LLM | LLM-01（推理）+ LLM-04（指令遵循）+ LLM-06（数学） |

输出：客观指标表 + 3个产出物，可初步判断模型水平。

### 2.2 完整评估（30分钟+，全量Prompt）

适合正式对比、参赛材料、量化损失分析。

步骤：
1. **16GB 可行性判定**（见第三节）— 先确认模型能跑
2. **参数固定** — 同对比组使用相同分辨率/步数/CFG/种子
3. **批量生成** — 用脚本跑全部标准 Prompt（见 `reference_data.md`）
4. **客观指标采集** — 脚本自动记录耗时/显存/成功率
5. **A/B 盲评** — 与基线模型并排对比，Elo 评分（见第四节）
6. **量化损失分析** — 如有多量化版本，绘制损失曲线（见第五节）
7. **填写模板** — 用 `templates/` 下的模板生成报告

## 三、16GB 显存可行性判定（核心模块）

> 这是本套件的特色：在生成前先判定模型能否在 16GB 卡上运行，避免 OOM 死机。

### 3.1 判定流程

```
模型文件大小 + 量化方式
        ↓
估算峰值显存 = 模型大小 × 1.2（中间计算开销）+ 1.5GB（系统底噪）
        ↓
峰值显存 < 14GB → ✅ 可行（留2GB安全余量）
峰值显存 14-15.5GB → ⚠️ 顶格（需独占GPU，生成前释放到<4GB）
峰值显存 > 15.5GB → ❌ 不可行（直接标记，不尝试）
```

### 3.2 判定表（必须填写）

每个模型评估前，先填此表：

| 项目 | 值 |
|------|-----|
| 模型名称 | |
| 量化方式 | |
| 文件大小 | |
| 估算峰值显存 | |
| 判定结果 | ✅可行 / ⚠️顶格 / ❌不可行 |
| 实际峰值显存 | （生成后填入） |
| 估算误差 | （生成后填入） |

> 常见模型的可行性参考见 `reference_data.md` 第四节。

### 3.3 安全规则

- 生成前必须释放显存到 **<4GB**（16GB卡安全线）
- 顶格模型（⚠️）必须独占 GPU，关闭 Ollama/其他服务
- 不可行模型（❌）禁止尝试，避免系统死机
- 显存采样间隔 0.5s（脚本默认），不要用1s以上（会漏峰值）

## 四、A/B 盲评 Elo 评分法

> 替代传统的 1-5 分绝对打分。绝对打分主观性太强，不同人/不同会话差异大。
> A/B 盲评是 Artificial Analysis Arena 等权威排行榜的做法，更可靠。

### 4.1 操作方法

1. 将**待评模型**与**基线模型**的输出并排展示（隐藏模型名）
2. 对每条标准 Prompt，强制三选一：**A更好 / B更好 / 一样好**
3. 累计对比结果，用 Elo 公式计算相对评分

### 4.2 Elo 计算公式

```
E_A = 1 / (1 + 10^((R_B - R_A) / 400))   # A的期望胜率

若A胜： R_A' = R_A + K × (1 - E_A)
若B胜： R_A' = R_A + K × (0 - E_A)
若平：  R_A' = R_A + K × (0.5 - E_A)

K = 32（默认），基线模型初始 Elo = 1000
```

### 4.3 分维度对比

不是只评"整体"，而是按维度分别 A/B 对比：

| 模态 | 对比维度 |
|------|---------|
| 图像 | 提示词遵循 / 美学 / 文字渲染 / 细节 / 构图 / 色彩 |
| 视频 | 提示词遵循 / 主体一致性 / 运动质量 / 时序连贯 / 画质 / 闪烁 |
| 音频 | 音质 / 风格符合 / 旋律 / 人声自然度 / 乐器分离 |
| LLM | 指令遵循 / 推理 / 知识准确 / 编程 / 多轮 / 创造力 |

每个维度独立 Elo，最后加权汇总（权重见 `reference_data.md` 第二节）。

### 4.4 什么时候用绝对1-5分

- 只有一个模型、没有基线对比时
- 需要快速给出直觉评分时
- 但**正式对比报告必须用 A/B 盲评**，绝对分仅作参考

## 五、量化损失曲线

> 同一模型不同量化版本（FP16→Q8→Q5→Q4）的质量衰减分析，是 16GB 环境下最有价值的评估之一。

### 5.1 测试矩阵

| 量化版本 | 文件大小 | 峰值显存 | 平均耗时 | A/B Elo（vs FP16） | 质量保留率 |
|---------|---------|---------|---------|-------------------|-----------|
| FP16 | | | | 基线(1000) | 100% |
| Q8 | | | | | |
| Q5 | | | | | |
| Q4 | | | | | |

### 5.2 质量保留率计算

```
质量保留率 = (量化版Elo - 1000) / (满分Elo - 1000) × 100%
```

### 5.3 决策建议

根据曲线给出推荐：
- **质量优先**：选质量保留率 >95% 的最高量化
- **显存优先**：选能在16GB运行的最低量化
- **甜点量化**：质量保留率 >90% 且显存节省 >30% 的版本

## 六、失败分类

生成失败不是简单记"失败"，必须分类，这本身就是重要指标：

| 失败类型 | 说明 | 常见原因 |
|---------|------|---------|
| OOM | 显存不足 | 模型太大/并发服务太多 |
| 超时 | 生成时间超过阈值 | 模型太慢/步数太多 |
| 输出损坏 | 文件无法打开/全黑/花屏 | 模型文件损坏/节点bug |
| 内容违规 | 生成了不安全内容 | 模型审查/提示词问题 |
| 加载失败 | 模型无法加载 | 格式不兼容/缺少依赖节点 |
| 其他 | 不属于以上 | 需详细记录错误信息 |

**失败率** = 失败次数 / 总尝试次数，是模型稳定性的核心指标。

## 八、注意事项

1. **公平对比**：同一对比组必须使用相同的 Prompt、参数、种子、硬件
2. **显存安全**：16GB 卡生成前必须释放到 <4GB，禁止显存打满
3. **多次采样**：A/B 盲评建议每条 Prompt 对比 2-3 次取稳定结论
4. **可复现性**：记录所有参数（步数、CFG、采样器、种子、分辨率、量化版本）
5. **量化影响**：同一模型不同量化版本必须分别评估，量化损失是核心指标
6. **基线选择**：A/B 盲评必须有明确的基线模型（如 SDXL 作为图像基线）
7. **中文测试**：图像必须包含中文文字渲染测试（IMG-02C），这是开源模型常见弱项
8. **结果持久化**：所有评估结果存入 `results/` 目录，便于历史对比
