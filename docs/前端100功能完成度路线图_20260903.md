### Day 1：API 层补全 + 认证修复（基础，0.5天）

**目标**：前端 api.js 封装所有41个可用API，为后续页面改造提供基础。

**改动文件**：`web/js/core/api.js`

**具体改动**：

1. **新增以下方法**（在现有方法后追加）：
```javascript
// 准入与预算
checkAdmission(body) { return this.post('/api/admission', body); },
getBudget() { return this.get('/api/budget'); },
getAdvice() { return this.get('/api/advice'); },

// QoS（注意：无 /api/qos/check，用 status 替代）
executeQos(body) { return this.post('/api/qos/execute', body); },

// 自动防护
saveAutoProtectConfig(body) { return this.post('/api/auto-protect/config', body); },

// 场景（注意：无GET /api/scene，场景列表从 registry 获取）
getSceneList() { return this.get('/api/registry').then(r => ({ ok: r.ok, scenes: r.scenes || {}, current: r.scene || 'unknown', error: r._rawError })); },
switchScene(body) { return this.post('/api/scene', body); },

// 门卫
guardAction(body) { return this.post('/api/guard', body); },

// 容器
stopContainer(body) { return this.post('/api/container/stop', body); },

// 桌面进程
killDesktopProcess(body) { return this.post('/api/desktop/kill', body); },
getDesktopVram() { return this.get('/api/desktop_vram'); },

// 日志与硬件
getLogs(query) { return this.get('/api/logs', query); },
getHardware() { return this.get('/api/hardware'); },

// 拓扑

// 可观测

```

2. **修复现有方法的参数名**：
   - `switchScene` 已有，但 `getScenes` 调用 `/api/status` 然后取 `r.scene`，应改为从 registry 取完整场景列表

3. **添加请求超时**（在 `request()` 方法中）：
```javascript

// ... fetch 时加 signal: controller.signal
// 成功/失败都 clearTimeout(timeoutId)
```

**验收**：
- [ ] api.js 包含所有41个API的封装方法

- [ ] 请求有30秒超时

## 五、风险与回退

1. **pages.js拆分风险**：拆分可能引入bug。应对：拆分前确保功能稳定，拆分后逐页面测试，保留原文件备份直到验证完成。
2. **场景切换进度模拟**：后端无步骤回调，前端模拟进度可能与实际不同步。应对：轮询status确认容器状态，模拟进度仅作视觉参考。
3. **/api/free超时**：显存释放可能耗时较长。应对：前端设置60秒超时（比默认30秒长），显示"正在释放显存..."进度提示。
