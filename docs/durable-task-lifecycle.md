# 持久任务生命周期

实现范围：GMae 管理的 ComfyUI 生成队列。代码位于 `16gb-ai-studio/vram-console/`；不覆盖外部直接提交任务或所有手动服务操作。

## 接受请求与提交

`POST /api/queue` 接受 `model`、`params` 和可选 `idempotency_key`。同一键与相同意图返回同一任务，改变参数返回 `IDEMPOTENCY_CONFLICT`（409）。界面同一次提交失败后重试保留键；刷新页面不保证保留该键，跨刷新或 API 重试应由客户端保存它。

任务意图在 SQLite 事务中保存后才返回接受成功。默认数据库为应用目录 `data/tasks.sqlite3`，可通过 `GMAE_TASK_DB` 指定。数据库及用户提示词不入 Git。存储不可用时拒绝接受（503），不退回内存模式。

生成请求前保存 `submitting` 和完整关联 ID；确认响应后保存真实后端 ID 和 `running`。响应丢失、提交后存储失败或结束证据无法保存时保留未知执行和 GPU 预留。协调器只在对应任务的结束证据成功落盘后释放预留。

## 启动恢复

服务器绑定端口后、启动后台资源操作和接受 HTTP 请求前恢复账本。存储失败中止启动。

- `queued`、`waiting_resource`、`precheck` 尚未进入生成提交，可重新准入；已有取消意图则结束。
- `submitting`、`running`、`uncertain` 恢复为未知执行，重新建立资源阻挡，禁止自动重放。
- 终态只恢复为历史记录，不重新执行。

多个未知记录逐个核验，解除一个预留时在同一锁内转移到下一个，不出现可供新任务抢占的空档。空队列或缺失历史不能单独证明执行已结束。关联 ID 对应的可信 ComfyUI `success`/`error` 历史与新鲜 GPU 读数可用于核验。对于已确认发送的指定任务取消，保存的匹配 ID 确认响应、严格读取的运行/等待队列均无该任务以及新鲜 GPU 读数也可作为取消结束证据；没有取消确认时不能仅凭队列缺失解除。

## 取消与限制

排队任务的取消先落盘，再移出队列。已进入提交或执行的任务保存取消请求，并在持有匹配任务预留时调用 `POST /api/jobs/{id}/cancel`。只使用指定任务接口，不回退全局 `/interrupt`。不支持该接口的旧版后端继续保存取消意图和等待结束。

取消确认响应并不立即解除资源预留。运行/等待队列仍有该任务、响应丢失或状态不可用时继续保留；结束证据落盘成功后才归入 canceled 并释放。canceled 表示取消请求已处理且任务已结束，不保证已经执行的输出被撤回。

实现依据为 [ComfyUI 官方源码](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/server.py)。本机 0.34.0 的源码特征及不存在任务的接口检查见 [协议证据](evidence/comfyui-cancel-protocol-2026-10-08.json)。这不代表真实 GPU 运行中断实验已完成。

应用层串行预留限定单进程、GPU 0；服务器默认端口绑定阻止同端口重复实例，不构成跨端口或跨进程 GPU 锁。手动操作已接入 [持久操作日志与启动阻挡](resource-operation-recovery.md)，无后端任务 ID 的可信解除仍待补齐。后端可能忽略客户端关联 ID、删除历史或失去可用性；这些情况下可能持续阻挡，不自动推断结束。

## 自动化证据

账本测试、提交边界测试及 `tests/test_durable_queue.py` 使用真实 SQLite 和受控外部适配器，覆盖并发幂等、请求前落盘、响应丢失、后端接受后进程退出、存储失败、恢复预留、多个未知任务、取消与提交并发。完整套件本阶段 352 项通过；前端模块与协调器行为检查通过，Python 名称检查无阻断错误。

当前完整测试增至 371 项通过，增加了指定任务取消传输、错误响应、身份隔离、等待结束证据及恢复后核验等 19 项测试。此前 352 项是接入基础的历史检查结果。

软件测试和不存在任务的真实接口检查不代表真实 GPU 任务中断通过。真实故障恢复实验、性能收益和跨进程所有权仍须独立验收。
