## 一、目标定义

### 终极目标
任何满足硬件要求（16GB+ NVIDIA 显卡、16GB+ RAM、150GB+ 磁盘）的机器，都能：
- **一键部署**：双击安装脚本，自动完成全部配置
- **一键升级**：运行升级脚本，数据不丢、可回滚
- **稳定运行**：全模态生成（文生图/图生图/文生视频/图生视频/AI写歌）可用

### 硬件要求（目标用户）
| 项目 | 最低要求 | 推荐配置 |
|------|----------|----------|
| GPU | NVIDIA RTX 3060 12GB | RTX 4060 Ti 16GB |
| 显存 | 12GB | 16GB+ |
| 内存 | 16GB | 32GB |
| 磁盘 | 150GB 空闲 | 300GB SSD |
| 系统 | Windows 10/11 或 Ubuntu 22.04+ | Ubuntu 22.04 LTS |
| NVIDIA 驱动 | ≥550.x（支持 CUDA 12/13） | 最新稳定版 |

## 二、三阶段路线图

### 阶段 1：可复现部署（现在 → 3个月）

**目标**：技术用户按文档 1-2 小时能部署完成。

**交付物**：
- [ ] 统一 `docker-compose.yml`（所有容器纳入编排）
- [ ] 模型清单 `models.json` + 下载脚本（自动下载 + SHA256 校验）
- [ ] 自定义 ComfyUI 镜像推送到公共仓库（阿里云 + Docker Hub）
- [ ] `.env.example` 配置模板
- [ ] 部署文档（Windows + Linux 双平台）
- [ ] 部署后健康检查脚本

**关键任务**：
1. 容器化 STT 服务（当前是宿主机 Python 脚本）
2. ollama 容器化（当前是宿主机安装）
3. 所有 IP/端口配置改为环境变量
4. ComfyUI 自定义镜像 build 流程文档化（Dockerfile）
5. 模型下载脚本支持国内源（ModelScope）和国际源（HuggingFace）

**验收标准**：
- 一台全新机器，按 README 操作，2 小时内能跑通 H3 视频生成
- 所有服务通过健康检查

---

### 阶段 2：一键部署（3 → 6个月）

**目标**：普通用户双击运行，30分钟-2小时完成（取决于网速）。

**交付物**：
- [ ] Windows 安装脚本 `install.ps1`
- [ ] Linux 安装脚本 `install.sh`
- [ ] 自动环境检测（GPU/驱动/磁盘/Docker/内存）
- [ ] 模型下载器（进度条、断点续传、多线程、校验）
- [ ] 自动配置生成（端口冲突检测、路径自动分配）
- [ ] 启动后自动健康检查 + 浏览器打开
- [ ] 卸载脚本（清理容器/镜像/模型，可选保留数据）

**安装流程**：
```
用户下载安装包 → 运行 install.ps1
  → 检测环境（GPU/驱动/磁盘/Docker）
  → 不满足则提示并退出（如驱动版本不够）
  → 拉取容器镜像（显示进度）
  → 下载模型文件（断点续传 + 校验）
  → 生成 .env 配置
  → docker compose up -d
  → 健康检查（每个服务轮询）
  → 打开浏览器 http://localhost:3000
  → 安装完成，显示访问地址和默认账号
```

**验收标准**：
- 非技术用户，无需命令行操作，能完成部署
- 安装失败时有明确错误提示和修复建议

---

### 阶段 3：一键升级（6 → 12个月）

**目标**：用户运行升级脚本，自动完成升级，数据不丢，可回滚。

**交付物**：
- [ ] 版本管理体系（Git tag + Docker image tag + models.json version）
- [ ] 升级脚本 `upgrade.ps1/sh`
- [ ] 配置自动迁移（版本间配置格式变化）
- [ ] 数据备份（升级前自动备份）
- [ ] 回滚脚本 `rollback.ps1/sh`
- [ ] 模型增量更新（只下载变化的文件）
- [ ] 升级后健康检查 + 失败自动回滚

**升级流程**：
```
用户运行 upgrade.ps1
  → 检测当前版本
  → 查询最新版本（GitHub/Gitee API）
  → 显示更新日志（changelog）
  → 用户确认升级
  → 备份配置和数据
  → 拉取新镜像
  → 更新模型（增量下载）
  → 迁移配置（如需要）
  → 重启服务
  → 健康检查
  → 成功：显示更新内容
  → 失败：自动回滚到上一版本
```

**版本号规则**：语义化版本 `MAJOR.MINOR.PATCH`
- MAJOR：不兼容的架构变化（如模型格式变更）
- MINOR：新增功能、新模型支持
- PATCH：Bug 修复、小优化

**验收标准**：
- 从 v1.0 升级到 v1.1，用户数据完整保留
- 升级失败能自动回滚，服务不中断超过 5 分钟

## 四、关键技术挑战与解决方案

### 挑战 1：自定义镜像分发（48GB）

**问题**：ComfyUI 自定义镜像（torch 2.13 + CUDA 13 + SageAttention + 自定义节点）48GB，用户不可能自己 build。

**解决方案**：
- 推送到**阿里云容器镜像服务**（国内速度快，免费额度够用）
- 同时推 Docker Hub（国际用户）
- 镜像 tag 与 Git tag 对应：`16gb-ai-studio/comfyui:v1.0.0`
- 提供 `docker-compose.yml` 直接引用镜像，用户无需 build

**优化（后期）**：
- 多阶段构建，减小镜像体积（目标 <20GB）
- 分层镜像：基础层（CUDA + Python）+ 依赖层（torch + ComfyUI）+ 自定义层（节点 + 配置）
- 模型不进镜像，单独下载

### 挑战 2：模型文件分发（~116GB）

**问题**：模型太大，不可能打包进镜像，CDN 带宽成本高。

**解决方案**：
- 不托管模型文件，只提供**下载清单和脚本**
- 国内用户从 **ModelScope（魔搭）** 下载，国际用户从 **HuggingFace** 下载
- `models.json` 清单包含：文件名、相对路径、大小、SHA256、下载URL（国内+国际）
- 下载脚本支持：断点续传、多线程、SHA256 校验、失败重试

**进阶**：
- 模型增量更新：对比 `models.json` 版本，只下载新增/变化的文件
- 可选 P2P 分发（BT/IPFS）降低带宽成本（用户量大时考虑）

### 挑战 3：配置管理

**问题**：当前 IP/端口硬编码，换机器就废。

**解决方案**：
- 所有配置通过 `.env` 文件管理
- `docker-compose.yml` 用 `${VAR}` 引用环境变量
- 提供 `.env.example` 模板，安装脚本自动生成 `.env`
- 配置项分类：必选（GPU 设备、模型路径）、可选（端口、日志级别、功能开关）

### 挑战 4：GPU 驱动兼容性

**问题**：CUDA 13 需要较新驱动（≥550.x），老用户用不了。

**解决方案**：
- 安装脚本检测驱动版本，不满足则提示升级链接
- 明确文档写明最低驱动要求
- 长期考虑：提供 CUDA 12 兼容版本（覆盖更多老用户），但维护成本高，第一版只支持 CUDA 13

### 挑战 5：Windows vs Linux 跨平台

**问题**：当前是 Windows + Docker Desktop，目标用户可能用 Linux。

**解决方案**：
- Docker 本身跨平台，compose 文件通用
- 安装脚本分两套：`install.ps1`（Windows）和 `install.sh`（Linux）
- 路径处理用 Docker 卷，不依赖宿主机绝对路径
- 文档双平台覆盖

## 五、风险评估

| 风险 | 影响 | 概率 | 应对 |
|------|------|------|------|
| 模型下载源不稳定（ModelScope/HF 挂了） | 高 | 中 | 提供备用下载源，脚本支持手动指定 URL |
| 自定义镜像太大，用户拉取慢 | 中 | 高 | 镜像优化（分层、瘦身），国内用阿里云 |
| GPU 驱动版本不兼容 | 高 | 中 | 安装前检测，明确最低要求 |
| Windows Docker Desktop 坑（WSL2 内存/性能） | 中 | 高 | 文档写清楚 WSL2 配置，推荐 Linux |
| 模型升级导致旧工作流不兼容 | 高 | 中 | 版本锁定，升级前备份，提供迁移指南 |
| 用户数据丢失（升级/卸载） | 极高 | 低 | 数据卷与系统分离，升级前自动备份 |
