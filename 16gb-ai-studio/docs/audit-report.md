## 二、🔴 严重问题（必须修复）

### S1. 命令注入风险（server.py）✅ 已修复（2026-08-25）

**位置**：`server.py:31-40` `run()` 函数 + `model_action()`

**修复（2026-08-25）**：
1. 新增 `_safe_model_name()` 正则白名单校验（`^[A-Za-z0-9._:/\-]+$`，长度≤128）
2. 新增 `run_args()` 使用 `shell=False` + 参数数组执行命令
3. `model_action()` / `docker_action()` / `ollama_stop()` 全部改用参数数组
4. `docker_action()` 增加 name/action 白名单校验

**原问题描述（保留参考）**：
`run()` 使用 `shell=True`，`model_action()` 的 `name` 参数未做白名单校验，直接拼接到命令中：
```python
def model_action(name, action):
    if action == "load":
        rc, out = run("ollama run {} --keepalive 30s".format(name), 300)
```
攻击者可通过 POST `/api/model` 传入 `name=;rm -rf /` 执行任意命令。

**影响**：远程代码执行（RCE），完全控制宿主机。

**修复建议**：
1. `name` 参数加白名单校验
2. 改用 `subprocess.run(cmd_list, shell=False)` 传参数组
3. 所有用户输入都经过校验再拼接到命令

### S2. 无认证的管理接口（server.py）✅ 已修复（2026-08-25）

**位置**：`server.py:298` 监听 `0.0.0.0:8787`

**修复（2026-08-25）**：
1. 默认监听地址从 `0.0.0.0` 改为 `127.0.0.1`
2. 新增环境变量 `VRAM_CONSOLE_HOST` 可覆盖监听地址
3. 新增可选 Token 认证：`VRAM_CONSOLE_TOKEN`，设置后所有 POST 和 `/api/status` 需带 `X-API-Key` 请求头
4. 监听非 localhost 且无 Token 时打印 WARNING
5. POST body JSON 解析失败返回 400（之前静默忽略）

**原问题描述（保留参考）**：
Web 服务无任何认证，暴露到局域网后，任何人都可以：
- 启停 Docker 容器
- 切换显存场景
- 加载/停止 Ollama 模型
- 间接通过 S1 执行任意命令

**影响**：局域网内任意设备可控制 AI 环境。

**修复建议**：
1. 默认监听 `127.0.0.1` 而非 `0.0.0.0`，通过环境变量开启外网监听
2. 加简单 Token 认证（请求头 `X-API-Key` 校验）
3. 文档中明确警告"勿暴露到公网"

### S3. 缺失依赖文件（game-on.ps1）✅ 已修复（2026-08-25）

3. 或暂时移除游戏态按钮

## 三、🟡 中等问题（建议修复）

### M1. run_comfy.js 无超时机制

**位置**：`run_comfy.js:40-71`

**问题**：轮询 ComfyUI 任务状态时无超时，如果 ComfyUI 挂了或任务卡住，脚本会**无限运行**。

**修复建议**：加 `--timeout` 命令行参数，默认 30 分钟，超时后退出并报错。

---

### M2. run_comfy.js 内部标识泄露

**位置**：`run_comfy.js:34`

**问题**：`client_id: 'dsh-ltx23-' + outPrefix`，前缀 `dsh-ltx23` 是内部项目代号，不应出现在开源代码中。

**修复建议**：改为 `client_id: 'local-ai-studio-' + outPrefix` 或随机生成的 UUID。

---

### M3. combo_switch 硬编码用户可能没有的模型

**位置**：`server.py:203-225`

**问题**：模型组合切换硬编码了 `qwen3.8:27b-rvn-q3km`、`qwen3.8:27b-iq3xxs` 等模型，普通用户可能没有这些模型，点击会报错。

**修复建议**：
1. 模型列表改为外部配置文件（如 `config.json`），用户按需修改
2. 或从 Ollama API（`/api/tags`）动态获取已安装模型列表
3. 对不存在的模型给出友好提示而非报错

---

### M4. h3-i2v.json 未说明图片输入要求

**位置**：`workflows/h3-i2v.json:6`

**问题**：工作流引用 `"image": "input.png"`，但没有说明用户需要先把图片上传到 ComfyUI 的 input 目录，且文件名必须是 `input.png`。

**修复建议**：在 `workflows/README.md` 中明确说明 I2V 工作流的图片准备步骤：
1. 将首帧图片放入 ComfyUI 的 `input/` 目录
2. 文件名改为 `input.png`（或修改工作流中的文件名）
3. 图片分辨率建议与工作流参数一致

---

### M5. Docker Compose 模板可能不可用

**位置**：`docker/compose-examples/README.md`

**问题**：
1. ai-dock/comfyui 镜像的启动参数不是通过 `COMFYUI_ARGS` 环境变量传递的（ai-dock 有自己的环境变量体系）
2. `--reserve-vram 2.5` 参数的传递方式未验证
3. 未说明国内镜像源替代方案

**修复建议**：
1. 实际验证 compose 模板能否正常启动
2. 按 ai-dock 官方文档修正环境变量名
3. 标注为"参考模板，需按实际环境调整"或提供验证过的版本

## 八、审计结论

这是一个**有真实技术价值的项目**，文档和工作流的质量显著高于平均开源水平。核心资产（显存调度方法论、H3/Music3 部署经验、踩坑集）具有可复用性。

但代码层面存在**两个高危安全隐患**（命令注入 + 未授权访问），在当前私有状态下风险可控，**但一旦公开或暴露到局域网/公网，风险极高**。

**最终建议**：
1. 私有状态下可继续使用和迭代
2. 公开前必须修复 S1-S3（约1.5小时）
3. 中长期建议补充测试和配置化，提升可维护性
