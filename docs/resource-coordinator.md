# 统一显存资源协调器

状态：已实现并提交[草稿 PR #2](https://github.com/Dannywjw-Git/GMae-16GAS/pull/2)。分支 `feat/resource-coordinator-20261008`，基于审计修复提交 `31c1f5f`。本文件记录软件验收和适用边界，不代表真实 GPU 性能验证。

## 目标与边界

将任务预算、模型加载、场景切换、手动释放、QoS 和空闲回收接入同一个资源所有权机制。预算引擎继续计算容量，协调器负责保证“检查—释放—复核—提交—等待结束”期间没有其他受管操作争抢或释放资源。

当前策略是单 GPU 0、串行执行。预留是应用内资源账本，不是驱动层显存配额，也不保证拦截直接访问 Ollama、ComfyUI 或 Docker 的外部程序。Ollama 没有在本实现中提供外部生成请求的可靠忙闲证据；不能将常驻模型等同于运行中的请求，也不能宣传为跨进程全局互斥。

## 实现结构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 所有权内核 | `core/resource_coordinator.py` | 原子申请、线程内嵌套借用、预留、不可变身份、状态快照、有限事件历史 |
| 决策策略 | `engine/coordinator.py` | 新鲜遥测、后端忙闲核验、登记预算、释放结果与提交前复核、可信结束核验 |
| 命令执行 | `core/resource_worker.py`、`api/resource_commands.py` | 单命令工作线程、最多 8 个执行或待执行命令、HTTP 等待超时不取消后台操作 |
| 任务执行 | `engine/queue.py` | 整个 ComfyUI 任务生命周期持有预留，等待资源、取消意图、状态未知时保留预留 |
| 观察接口 | `api/endpoints/coordinator.py` | 状态读取、无副作用预览、通过后端历史核验结束 |
| 页面 | `web/js/pages/queue.js` | 显示资源所有者、阶段、等待原因和待核验状态 |

资源所有权在慢速适配器调用前获取。元数据锁仅保护短操作；读取状态不等待后端请求。嵌套受管调用借用同一预留，不能提前释放外层所有权。

## 关键约束

1. 同一时刻只有一个外层受管操作持有 GPU 所有权。其他操作得到 `RESOURCE_BUSY` 或任务进入 `waiting_resource`。
2. 不接受前端自行声明的容量。模型峰值来自登记配置；未登记的上下文参数、未知容器启动峰值和不可用遥测均拒绝执行。
3. 释放确认不是容量确认。释放返回成功后还必须读取物理显存；实际提交前再检查预算。
4. ComfyUI 运行或待执行队列不为空时拒绝释放。忙闲接口失败也拒绝继续。
5. 提交响应丢失、结束轮询超时或意外异常进入 `uncertain`，保持预留。取消请求本身不证明后端结束。
6. 核验仅接受对应完整任务 ID 的 `success` 或 `error` 历史记录，并检查新鲜遥测。空队列、客户端提供的“完成”声明或其他任务记录都不能解除预留。
7. 核验解除预留后同步匹配的队列任务状态。身份或任务 ID 不匹配时不修改队列记录。
8. 失败释放中止场景或模型组合切换；HTTP 边界不把拒绝或失败包装为成功。

## 接入范围

| 操作 | 入口 |
| --- | --- |
| 生成队列 | `_run_task`、`_queue_submit_comfy`（要求活跃预留） |
| 模型加载、停止 | `load_model_api`、`model_action`、Ollama 停止函数 |
| 场景与组合 | `scene_switch`、`combo_switch` |
| 容器操作 | Docker 启动、重启、停止、暂停、恢复和 `free_all` |
| ComfyUI 释放 | `comfy_free` |
| 手动进程结束 | `desktop_kill`、`POST /api/process/kill` |
| 统一释放策略 | `gpu_guard_evict` |
| QoS | `qos_execute`、自动保护操作 |
| 空闲回收 | `_reap_service` |

HTTP 资源修改端点通过命令工作线程执行；任务队列和已有后台策略仍使用各自工作线程，但共享同一个协调器。没有新增常驻 watchdog。

`GET /api/qos/check` 只观察和生成建议，不在请求线程中执行释放。既有 QoS 后台循环仍可通过协调器运行自动保护。

## API 与配置

- `GET /api/coordinator`：账本状态及有限历史，即使遥测不可用仍可读取。
- `POST /api/coordinator/preview`：模型、来源和可选上下文的建议，不预留、不释放；执行时必须重新准入。
- `POST /api/coordinator/reconcile`：从后端读取真实历史；请求体不能提供解除预留的证据。

容器登记项需要显式提供非负有限数值 `startup_vram_gb`。该字段代表容器冷启动、重启或恢复的附加 GPU 显存预算。必须根据目标机器实际校准后填写；当前实现不补造默认实测值。模型登记预算也只适用于所登记的参数配置，不等于参数任意变化后的准确峰值预测。

## 验证与剩余验收

离线测试使用真实协调器、预算及服务调用路径，仅替换 GPU、网络和容器适配器。已覆盖真实线程互斥、慢速评估期间的所有权、嵌套调用、状态隔离、跨入口阻挡、释放失败、陈旧遥测、启动预算拒绝、执行未知、取消意图、可信核验、HTTP 超时和命令拥塞。具体结果应以分支最终测试输出与 CI 为准。

最终本地软件验证：323 项测试通过，其中 7 项使用临时本机随机端口验证真实 HTTP 路由，不连接真实模型服务。前端实际页面方法的行为测试通过，包括未知状态、等待提示、失败预算禁用提交、取消 ID 和接口失败展示；前端语法/导入检查无错误；Python 阻断级名称错误为 0（保留 66 项历史 lint 警告）。已核查资源修改入口并更新交接记录。

ComfyUI 的客户端任务 ID 支持取决于后端版本；实现依据[官方 server.py 的提交与历史接口](https://github.com/Comfy-Org/ComfyUI/blob/master/server.py)。旧版若忽略客户端任务 ID，丢失提交响应时可能无法匹配历史，协调器继续保留预留。
