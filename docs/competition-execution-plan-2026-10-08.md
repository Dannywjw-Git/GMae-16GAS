Work 会话负责主要技术执行，另一个 Chat 会话负责战略、架构复核、竞争力评估与独立质量监督。GitHub 是唯一共享事实来源；不依赖隐藏记忆、未提交文件或非公开推理，也不假定另一会话会自动收到提交或开始评审。

每个重要阶段使用独立分支和 Draft PR，推送代码、测试证据及 [项目状态](PROJECT_STATUS.md)、[决策记录](DECISIONS.md)、[交接记录](HANDOFF.md)。交接明确 commit、PR、通过的测试、已知缺陷、未验证能力、建议下一步和独立评审内容，区分已实现、自动化测试通过与真实 GPU 验证通过。

持续推进最高优先级任务，不等待 Chat 反馈；建议以证据评估，采纳或冲突理由写入决策记录。重大设计缺陷和验收阻断优先修复。普通工程决策自主处理；重大方向变更与下述审批事项保留用户授权。

## 当前最大瓶颈：任务生命周期

任务账本采用标准库 SQLite，不引入数据库服务。任务意图、幂等键及参数摘要在同一事务内保存；状态更新采用版本比较，避免取消和执行线程互相覆盖。后端相关 ID 一旦登记不能被覆盖。

必须在发出生成请求之前提交 `submitting` 检查点；随后记录真实后端 ID。恢复时，queued/waiting/precheck 可重新准入，submitting/running/uncertain 必须先核验，不能直接重放。接受请求后丢失响应是核心故障场景，不能用“没有历史记录”推断“没有执行”。

下一步接入队列、协调器预留与服务器启动，统一所有状态写入，并实现后端支持范围内的定向取消。证据不足时保留未知状态和资源阻挡，界面必须说明下一步。
