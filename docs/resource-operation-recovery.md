# 资源操作的持久保护

范围：正式服务器启动后，所有经过统一协调器的资源操作。操作日志与任务账本共用 `GMAE_TASK_DB`（默认 `data/tasks.sqlite3`），本地数据不入 Git。

协调器在首次进入 running/releasing/stopping 阶段前保存操作意图，包含操作、服务、模型和所有者，不保存提示词。准入中的模型释放同样记录。仅做预检且未触发资源变更的拒绝不产生待恢复操作。嵌套适配器共用外层日志，不重复占有资源。

适配器返回且明确进入 completed/failed 后保存结束记录；异常或无法保存结束记录时，日志及当前资源预留均保持未知。下一次正式启动先恢复操作日志，再恢复任务队列，随后才启动后台资源操作和 HTTP 服务。未知操作不自动重放。

生成操作与任务账本关联：已提交且状态未知的任务以其持久关联 ID 恢复一个预留，同时绑定操作日志；核验先保存任务和操作日志的终态，再解除预留。两份终态写入不是同一事务，重复核验允许匹配的任务终态，避免部分保存失败后无法重试。

## 命令尝试与回执

资源变更阶段的外部命令增加独立尝试 ID，在启动进程前保存所属操作及参数。返回码为 0 且回执成功保存后，该命令才确认完成。超时、非零退出或回执保存失败都保留未知状态；外层不能把它重新解释为普通失败并释放预留。PowerShell 脚本共用此边界。Docker ps/inspect 等只读查询不记录为资源变更。

尝试 ID 是本地关联身份，不是 Docker daemon 的执行 ID。正式运行路径由独立的一次性执行者写回执：先保存 dispatch_pending，执行者原子领取为 inflight 后才启动命令。主进程退出不会阻止仍存活的执行者保存结果，重复领取不执行命令。成功状态与输出在同一事务中保存，输出最多保存末尾 64 KiB。

Windows 执行者以隐藏窗口与新进程组启动；POSIX 使用独立会话。执行者本身被终止、机器重启、请求超时或未领取的意图仍可能未知，不自动重新派发。参数和输出可能包含本机路径及运行信息，只保存在已排除出 Git 的本地数据库，不能公开数据库作为竞赛证据。

## 限定的可信解除

明确标记为仅一条容器控制命令的 start/stop/restart/pause/unpause，解除预留须匹配操作身份、受管目标、返回码 0 的持久回执、fresh inspect 目标状态及新鲜 GPU 读数。stop 要求已停止且未暂停；pause 要求运行且暂停；start/restart/unpause 要求运行且未暂停；死亡、重启中、查询失败或状态不匹配均阻挡。确认的是原命令结束与当前容器目标状态，不代表 GPU 空闲，暂停尤其不证明显存释放；下一项操作必须重新准入。操作终态保存失败时保持预留，后续核验可重试。

该路径拒绝混合操作、脚本、容器内 exec、旧版日志、不匹配目标、未完成及非零回执。启动时最多核验 32 条已恢复的未知操作，遇到缺失证据立即停止；仍未结束的执行者稍后保存回执后，可通过已有资源核验接口再次核验。未添加后台看门狗，也不重放中断流程。

## 验证与当前限制

完整离线套件 380 项通过。新增 8 项操作日志测试及 1 项队列联合恢复测试，覆盖请求前落盘、存储失败禁止适配器、结束保存失败保留预留、无变更的准入拒绝、准入释放异常、嵌套操作、外层异常和适配器进入后子进程退出。

命令回执接入后完整套件增至 388 项通过，新增 8 项验证请求前落盘、禁止未落盘命令、真实受控子进程超时、回执写入失败、禁止带未知命令确认操作、只读查询区分和非零退出。真实 Docker/Ollama 故障仍未验证。

独立执行者阶段完整套件增至 407 项通过，新增 19 项进程与核验测试。父进程立即退出后结果仍保存、重复执行者仅执行一次、回执事务失败保持未知，以及有限容器恢复的正反例均通过。进程实验使用受控 Python 命令，不代表实际 Docker 或 GPU 故障实验通过。

这些不是实际 Docker/Ollama 崩溃或 GPU 实验。超出限定容器命令的未知操作仍缺少完整自动解除路径；不能仅根据进程重启、低显存或空队列推断原命令已结束，也不能清空数据库绕过。目标状态按受管容器名称核验；日志尚未记录命令前容器 ID，不能证明容器未被外部替换。

## 正式服务器的跨进程所有权

正式入口在绑定端口、恢复账本和启动后台线程之前取得系统文件锁，持有到进程退出。同一系统账户的不同端口、检出目录共用 GPU 0 锁（Windows：LOCALAPPDATA/GMae/gpu0.lock；POSIX：用户数据目录/GMae/gpu0.lock）。另一实例立即拒绝启动。崩溃由操作系统释放锁，不删除持久恢复事实；新实例必须读取原 GMAE_TASK_DB 并安装未知操作预留。

锁文件保留账本绝对路径。不同检出必须显式设置 GMAE_TASK_DB 指向首次启动所用账本；路径不符或元数据损坏时拒绝启动，不自动迁移或清空。正常退出也保留账本身份。禁止运行时删除/替换锁文件或数据库。

范围为同一 OS 账户使用正式入口的实例；不约束其他账户、旧版服务器、外部 Docker/GPU 客户端或直接导入适配器的脚本。系统锁恢复不代表后端任务结束。450 项完整离线测试通过；新增 12 项验证真实 OS 子进程竞争/杀进程后的锁恢复、原账本未知预留、容器查询解析与目标状态阻挡。尚未执行两个完整 GMae 服务及真实 GPU 故障实验。

操作日志在正式服务器启动时启用。仅导入模块并单独调用适配器的外部脚本，必须调用 `restore_resource_operations()` 完成初始化；离线测试使用隔离账本。未启用日志的第三方调用不属于此持久恢复保证。
